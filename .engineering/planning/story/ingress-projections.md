## Outcome

Each export of an ingress gets its projection, generated, never authored: for `http` an
`ess-http/1` protocol binding over exactly the interface's operations (paths left open) and the
OpenAPI from `ess generate --kind openapi --http`; for `event_stream` the stream list (per scope
the events it carries, resumable from a cursor); for `cli` an `ess-cli/2` binding; for `tool` a
tool list (one tool per command with its input schema from `--kind schema` and description from
`naming.summary`, one read tool per view, names the ESS wire names); for `agent` an agent card; for
`metrics_scrape` a metric list (catalogue id, summary as help, unit, labels architecture, part path,
instance, every KPI a gauge). Each is committed with `sources.sha256`, held by a fast digest check,
and regenerated byte for byte in the `slow` lane. If `ess-http/1` cannot project a subset of a
component's surface, the gap is filed in ESS with a reproduction. Design: `design/ingress.md` I7,
Q7 A. Epic: `epic:ingress`.

## Scope

- A projection module per protocol (inferred: `crates/agenticspec-sim/src/ingress/`) and the
  command that writes them, declared in `spec/cli.yaml` and `spec/domains/cli.yaml`;
  `crates/agenticspec-cli-contract/` regenerated; `crates/agenticspec/src/main.rs` dispatches it.
- The workstation projections, committed with `sources.sha256` (inferred: `generated/ingress/`).
- `scripts/check-generated.sh`, `Taskfile.yml`: the digest check and the slow lane.
- Tests, `docs/` reference of each projection, `CHANGELOG.md`.
- Builds and tests through `slot`; no test over 60 s, the test step within 120 s, a pool job over
  10 minutes is killed.

## Acceptance

- Given the workstation example, when the projections are generated, ingress `user`'s OpenAPI
  holds exactly 2 command operations and one GET per resolved view, and `ess` validates the
  protocol binding.
- Given ingress `operator`, when its tool list is generated, it holds 3 command tools
  (`drain-gateway`, `stop-gateway`, `detach-upstream`) and one read tool per resolved view, each
  with an input schema.
- Given ingress `metrics`, when its metric list is generated, it holds 5 gauges with the
  catalogue's units and the labels architecture, part path and instance.
- Given a changed block file, when `task check:generated` runs without regeneration, it fails
  naming the stale projection's digest; after regeneration it passes.
- Given the generator run twice on the same inputs, both runs write the same bytes.
- Given the test step, when it runs, no test runs over 60 s and the step ends within 120 s.
