## Outcome

The studio's UI is ours, generated by our own generator from an `ess-ui/1` document, not drawn by
the ESS tooling. The owner, 2026-11-28, on the first slice's page: the look of what ESS gives is not
acceptable; the UI is to be generated from the ESS UI spec by a generator of this repository, into
components whose look this repository controls.

- **Source:** `studio/studio.ui.yaml`, an `ess-ui/1` document of the studio's pages, reads,
  commands and channels, checked by `ess ui check --model studio`. It may itself be generated from
  other structured data later; the generator does not care where it came from.
- **Generator:** `crates/agenticspec-ui` (Rust): reads an `ess-ui/1` document (after `ess ui
  check` accepts it) and writes Vue 3 single-file components and TypeScript, one per page and per
  overlay, plus the router and the typed client of its reads, commands and channels. Its output is
  committed under `ui/studio/src/generated/` and held by `scripts/check-generated.sh` (`task
  check:generated`), like every other generated directory.
- **Design system:** `ui/kit/` (hand-written, Vue 3 and TypeScript): design tokens (colour, type,
  spacing, radius, motion) with a light and a dark theme, and the components the generator targets
  (shell, page, toolbar, table, metric, chart, form, field, button, badge with a tone, empty and
  error states, toast, dialog, split pane, code box). The generator emits only kit components and
  slots; every look lives in `ui/kit/`, so restyling never touches the generator.
- **Host slots:** what no `ess-ui/1` construct can say (the interactive architecture graph, the
  patch editor with its syntax) is a hand-written kit or studio component placed through the
  document's host slot, never a hand edit of generated output.
- **Framework:** Vue 3, Vite and TypeScript, as `ui/app` already uses; vitest and Playwright on
  fixtures.

## Scope

- `crates/agenticspec-ui` (new): the reader of `ess-ui/1` (typed from the schema
  `schemas/ui/ess-ui.schema.yaml` of the ESS release `blocks/ess-inputs.yaml` requires), the Vue
  emitter, a CLI `agenticspec ui generate --path <doc> --out <dir>` (declared in `spec/cli.yaml`;
  the CLI is generated), golden tests on small documents.
- `ui/kit/` (new): tokens, themes, components, a page of every component in both themes for
  review, vitest.
- `studio/studio.ui.yaml` (new): the first slice's page (architecture list, draft view with graph,
  patch box, check result, refusal) as an `ess-ui/1` document.
- `ui/studio/` (new): Vite app; `src/generated/` from the generator; host-slot components;
  `crates/agenticstudio` serves its build in place of `crates/agenticstudio/assets/studio.html`,
  which is removed.
- `Taskfile.yml`: `ui:generate`, `check:ui-kit`; `check:studio` runs against the built app.
- Tests: each ends within 60 s, the step within 120 s; the browser tests start one server per run.

## Shared surfaces

- `ui/studio`, `crates/agenticstudio`: this story creates `ui/studio` before
  `story:studio-editor`, which depends on it and adds the editor's pages to `studio/studio.ui.yaml`
  and its host slots; every later studio story extends the document and regenerates.
- `spec/cli.yaml` and the generated CLI crate: one more command group.
- `scripts/check-generated.sh`: one more line.

## Acceptance

- Given `studio/studio.ui.yaml`, `ess ui check --path studio/studio.ui.yaml --model studio` exits
  0, where before no such document existed.
- Given that document, `agenticspec ui generate` writes `ui/studio/src/generated/`, and running it
  again changes no byte (`task check:generated` passes).
- Given a change of one token in `ui/kit/` (the accent colour), the built studio page shows the new
  colour and no file under `ui/studio/src/generated/` changes.
- Given `agenticstudio serve`, the browser tests of `story:studio-first-slice` (set patch to
  revision 2; unknown verb refused at rule 2, revision unchanged) pass against the generated app,
  and `crates/agenticstudio/assets/studio.html` no longer exists.
- Given the built app in both themes at 1366x768 and 390x844, axe reports 0 serious or critical
  violations and no element runs past the viewport horizontally.

## Not in this story
