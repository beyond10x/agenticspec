A team without an orchestrator on one repository resolved 19.31% at 1 agent and 28.78% at 128, with a typed board of length-limited entries (2609.26781); that study started one agent every 30 s, then every 3 s. The simulator charges each read of a post by an idle copy one model call and counts a claim conflict when a reader reads within `claim_window_seconds` of the copy that claims; a start stagger holds copies back so that a burst of posts is claimed one by one. A post that finds the team at its limit is offered again when a run ends. The simulator does not model the board's entry kinds and length limits, entries other than tasks (facts, failures, patch summaries), a reader that is busy while it reads, nor any effect of the team's size on how often a task succeeds."
