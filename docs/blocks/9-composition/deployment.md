An architecture revision brought to a runtime, and the runs it serves. An installation puts one architecture revision on one runtime with a binding (which concrete thing plays each part); a runtime holds one Active installation at a time. Draining takes no new run and lets the runs it holds end; a rollback ends the current installation and makes the one it replaced Active again. An architecture run is one run of an installation for one subject: queued, running, waiting, and done, failed or cancelled. It keeps the revision and binding of the installation it was queued on, so a newer revision never changes a run already queued. The caller names a run's identity once per intent; a repeat with the same identity starts nothing. A deployment brings one revision onto one scope of a target: agenticspec admits it with its contract, binding and packing and writes its bundle (`agenticspec-deployment/1`), a translator turns the bundle into its target's architecture, and the target realizes it and reports how its units run. It records each step by digest and its target and scope by value, as ESS declares no relation across systems. A request is refused before anything is recorded when the revision is not released (an in-process run takes a draft), when admission names findings, or when the scope is taken; a recorded deployment is refused later by its translator's coverage or by its target, each by name with its findings.
