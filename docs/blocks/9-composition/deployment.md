An architecture revision brought to a runtime, and the runs it serves. An installation puts one architecture revision on one runtime with a binding (which concrete thing plays each part); a runtime holds one Active installation at a time. Draining takes no new run and lets the runs it holds end; a rollback ends the current installation and makes the one it replaced Active again. An architecture run is one run of an installation for one subject: queued, running, waiting, and done, failed or cancelled. It keeps the revision and binding of the installation it was queued on, so a newer revision never changes a run already queued. The caller names a run's identity once per intent; a repeat with the same identity starts nothing.
